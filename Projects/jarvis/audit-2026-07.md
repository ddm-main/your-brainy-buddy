Snapshot taken during Round 3 of the post-launch hardening effort, against Deepak's full "Complete Application Audit, Refactor & Production Readiness" spec. Rounds so far: **1** RLS/secrets/auth hardening (done), **2** Finance Intelligence Layer — net worth/health-score/reconciliation (done), **3** security & correctness hardening (this round). Everything below reflects the codebase state at the *start* of Round 3, before this round's fixes — see `_overview.md`'s log for what Round 3 actually shipped.

## 1. Application audit — module by module

### HUD (`src/routes/Home.tsx`)
- **Mission Control**: shows today's focus tasks + next-7-days due tasks only. Missing: meetings, bills, EMIs, goals, AI suggestions, statement/finance alerts.
- **Daily Brief**: genuinely AI-generated (reads `jarvis_interactions`, fed by both a manual "refresh" button and the morning-briefing poller in `src/lib/briefing.ts`).
- **Signal**: functions as a computed alerts widget (overdue tasks, blocked projects, finance due-in-7d, unfired reminders) — not the app's notification center; that's the separate TopBar bell.
- **Pulse**: still shows only "this month net worth" via `db.transactions.monthSummary()` — confirmed **zero** references to `financeMetrics.ts` anywhere in `Home.tsx`/`src/components/`, despite that module (net worth, credit utilization, health score) shipping in Round 2. Real gap: Pulse should be wired to it.

### Tasks (`src/routes/Tasks.tsx`)
Has: priority, focus flag, due date, status, filter tabs, category chip, delete. Schema has unused `linked_account_id`/`linked_email_id`/`linked_goal_id`/`linked_project_id` columns — dead, no UI or tool ever reads/writes them. Missing entirely: subtasks, recurrence, calendar/Kanban/timeline views, attachments, AI suggestions.

### Notes (`src/routes/Notes.tsx`)
Plain textarea, autosave on blur — not rich text or markdown. Schema has unused `summary` and `linked_project_id` columns (dead). Missing: images, voice notes, search, tags, real AI summary, backlinks, task links.

### Projects (`src/routes/Projects.tsx`)
List + detail view with status/priority/description/next-action/blocker + a free-text updates log. Missing: Kanban, timeline, files, embedded tasks/notes, budget, milestones, finance integration — none of these exist in schema or UI.

### JARVIS assistant
24 tools defined server-side in `jarvis-chat/index.ts`, but the client dispatcher (`jarvisTools.ts`) only wires 7 of them to UI intents — the other tools succeed silently with no content card. `SYSTEM_PROMPT` has no injection of current route/app-state, so JARVIS doesn't know what screen Deepak is on. No global search, no deeper automation beyond one-shot reminders. **Bug found and fixed this round**: `create_task`/`create_note` were being inserted twice (once server-side by the tool, once again client-side by `runToolIntent`) — every voice/chat-created task or note was silently duplicated.

### Link module
**Does not exist.** No route, component, or file named "Link" anywhere in the app — not a stub, genuinely unbuilt. Needs an explicit decision: build a Knowledge Hub, or drop the ask.

### Notifications
`notificationStore.ts` is a flat, uncategorized, in-memory list (wiped on refresh, no DB table) fed by exactly one source — the `jarvis_reminders` poller. No categorization by bills/EMIs/cards/statements/tasks/projects/goals/AI/security; nothing from Finance, Tasks, or Projects feeds it today.

### Config (`src/routes/Config.tsx`)
Flat 4-tab structure: Home / Email / Finance / Projects. The Finance sub-nav (Banks/Accounts/Cards/Loans/Goals/Subscriptions) is real and matches spec. Missing sections entirely: Appearance, dedicated AI/brain settings (currently only reachable inside the JARVIS voice overlay), Notifications, Security, Automation, Backup, Import/Export, Developer.

## 2. Security audit

### Confirmed: Gmail-connect flow leaked internal details (Deepak's specific complaint)
Traced end-to-end. Two real leak classes, both fixed this round:
1. **Raw Postgres/Google errors reaching the browser** via a `gmail_error` redirect query param — e.g. `duplicate key value violates unique constraint "email_accounts_user_google_sub_uniq"` on a reconnect attempt, rendered verbatim in `EmailAccountsList.tsx`.
2. **Literal internal remediation copy** in a `hint` field on server-misconfiguration responses — e.g. *"Add the secret in Supabase → Edge Functions → Secrets, then redeploy."* — shipped straight into the connect-Gmail UI.

Fix: server-authored generic messages + full detail moved to `console.error` (inspectable via Supabase logs), short static error codes for the OAuth redirect path. Google's own OAuth `error`/`error_description` (the legitimate RFC 6749 surface, e.g. user denying consent) is deliberately left untouched.

### Confirmed: the same raw-error-to-client pattern in ~15 other edge functions
Every edge function logged correctly server-side but also returned the raw exception message in its JSON response — `gmail-sync`, `gmail-message`, `gmail-sync-due` (had **no** server-side logging at all), `finance-extract`, `finance-retry-statement`, `finance-set-statement-password`, `finance-statement-pdf-url`, `finance-upload-statement`, `jarvis-vision`, `jarvis-vision-upload`, `jarvis-tts`/`jarvis-transcribe` (also forwarded raw upstream Lovable-AI-Gateway error bodies), and 11 tool-level sites inside `jarvis-chat`. Also client-side: `db.ts`'s `emailAccounts.create`/`update` let a raw Supabase error reach a toast. A special case: `_shared/gmail-sync-core.ts` persists sync errors into `email_accounts.last_error`, a DB column rendered *persistently* (not just a transient toast) in the UI.

Fix: two new shared helpers (`supabase/functions/_shared/errors.ts` server-side, `src/lib/errors.ts` client-side) — generic message + correlation ref to the client, full detail to logs/devtools console, applied everywhere above.

### Confirmed: zero rate limiting on 4 of 5 AI endpoints
`jarvis-chat` already had a real two-layer scheme (20/min sliding window + 500/day durable quota). `jarvis-tts`, `jarvis-transcribe`, `jarvis-vision`, `jarvis-vision-upload` had none, despite all calling paid upstream APIs.

Fix: extracted the sliding-window algorithm into a shared, reusable module (`_shared/rate-limit.ts`); gave the daily quota table an `endpoint` dimension (migration `20260712120000_jarvis-usage-per-endpoint.sql`) so continuous voice dictation (which polls `jarvis-transcribe` every ~2.5s) can't exhaust the budget that gates legitimate chat requests; added per-endpoint sliding-window + daily caps to all 4 previously-unprotected functions.

### Not substantiated
CORS is a real allowlist (`_shared/cors.ts`), not wildcard, on every function — no fix needed there. RLS, the `oauth-state.ts` fail-closed secret, and the `gmail-sync-due` CRON_SECRET fail-closed check (all fixed in Round 1) were re-verified intact, not reverted.
