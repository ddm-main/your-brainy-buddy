# JARVIS — Phase 0 Full Audit (2026-07-12)

Scope: full read of every route, component, store, hook, edge function, migration, RLS policy, storage policy, shared lib. Findings grouped by module with severity (**P0** blocker · **P1** high · **P2** medium/polish), evidence (`file:line`), and recommended fix. **No code was changed in this phase.**

---

## Executive summary

The backend is in good shape. **RLS is enabled and owner-scoped on every one of the 31 public tables** (verified via `pg_policy`), the two storage buckets (`jarvis-vision`, `statement-pdfs`) have per-user path-prefix policies, statement passwords are AES-256-GCM encrypted server-side with an edge-only secret, edge functions validate JWT via `getClaims` and route errors through `sanitizeError` with correlation refs. The rewriting shrinks to three real workstreams:

1. **Frontend info-leak clean-up** (P0/P1) — every error surface currently prints raw `Error.message`, which today includes edge-fn URLs (`.../functions/v1/gmail-oauth-start`), Supabase project host, statement password parse errors, and internal UUIDs. This is the specific complaint that triggered the plan.
2. **Finance completion** — parsing pipeline OK, but UI is incomplete (no card/loan/sub detail pages, no reconciliation UI, no subscription auto-detect), interconnection is loose, and the Overview page reaches into edge functions directly instead of through `db`.
3. **HUD, Tasks, Notes, Projects** — HUD Mission Control has real data on some tiles but stubs on Pulse/Signal; Tasks lacks subtasks/recurring/kanban; Notes/Decisions have working editors but no rich text/backlinks; Projects is a shell.

Blocker-count for Phase 1: **~8 P0/P1** items, all frontend or config, no schema migrations required.

Rollup counts: **Bugs 6 · Missing features 12 · UI 9 · Perf 5 · Security 7 · DB 3 · UX 8 · Code 6 · Refactors 5**.

Both `jarvis-vision` and `statement-pdfs` have owner-scoped `(storage.foldername(name))[1] = auth.uid()::text` policies for SELECT/INSERT/UPDATE/DELETE. **Correct.**

### `user_roles`
No `user_roles` table exists (this is a single-user personal OS — `block_new_signups()` trigger hardcodes Deepak's UUID). Confirmed intentional. If Phase 4 adds any multi-user surface (Knowledge Hub sharing?), the `user_roles` + `has_role()` pattern from the system prompt becomes required.

- Password protection score / minimum length not enforced beyond default.
- No account-deletion endpoint. When Deepak wants to nuke everything, RLS cascade goes through `on delete cascade` from `auth.users`, verified on `user_roles`-analogous rows — but Gmail/Azure refresh tokens are not revoked upstream.

## Section 5 — Security headers

`index.html` sets:
- CSP: `default-src 'self' https: wss: ws: blob: data:; script-src 'self' 'unsafe-inline' 'unsafe-eval' https:; …` — **too permissive**: `'unsafe-inline'` + `'unsafe-eval'` in `script-src` disables meaningful CSP protection.
- `Referrer-Policy: no-referrer` — good.
- `Permissions-Policy` correct.
- Missing: `X-Frame-Options: DENY` (or `frame-ancestors 'none'` in CSP).
- Missing: `X-Content-Type-Options: nosniff` (Supabase serves this by default; Lovable static hosting probably too, but add to CSP `<meta>` for defence-in-depth is not possible — must set via hosting config).

| # | Sev | Finding | Fix |
|---|-----|---------|-----|
| H1 | P1 | `script-src 'unsafe-eval'` — Vite React Refresh in dev needs this; Framer Motion doesn't. Prod build likely doesn't need `unsafe-eval` at all. | Phase 1: split CSP dev/prod; prod drops `unsafe-eval`. |
| H2 | P1 | No `frame-ancestors` — clickjacking possible. | Phase 1: add `frame-ancestors 'none'` to CSP. |
